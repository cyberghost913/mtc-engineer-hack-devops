# Сдача решения MTC ENGINEER HACK

Источник требований: предоставленный документ «Кейс DevOps (MTC ENGINEER HACK)».
Этот список не заменяет условия организаторов.

## Формат загрузки

- Архив: `Фамилия.zip`, фамилия точно как при регистрации, не более 18 МБ.
- В корне архива ровно два файла: `Ссылка.txt` и `Паспорт.pdf`.
- `Ссылка.txt` содержит только URL ветки `main`, без пояснений.
- Паспорт: не более 4 страниц и 15 МБ. Выбран PDF, соответствующий явно указанному имени файла.
- Полное решение размещается в публичном Git-репозитории в ветке `main`.
- Репозиторий должен клонироваться без авторизации и оставаться публичным до публикации финалистов.
- Сдача: до 4 октября 23:59; часовой пояс и год в формулировке срока не указаны.
  Часовой пояс нужно уточнить у организаторов. После дедлайна ветку решения менять запрещено.
- Архив загружается кнопкой «Загрузить» на странице задания. При замене используется
  «Загрузить другой файл»; новый архив заменяет предыдущий.

Исходники не нужно добавлять внутрь конкурсного архива: они находятся в репозитории.
Архив `devops-foundation.zip` из подготовки проекта не является конкурсным архивом.

## Минимальная проверка перед окончательной сдачей

На чистой отдельной Ubuntu Server 24.04, согласно README:

```bash
make setup
make doctor INVENTORY=inventory.local.ini EXTRA_ARGS='--ask-become-pass'
make bootstrap INVENTORY=inventory.local.ini EXTRA_ARGS='--ask-become-pass'
make deploy INVENTORY=inventory.local.ini EXTRA_ARGS='--ask-become-pass'
make verify-all INVENTORY=inventory.local.ini EXTRA_ARGS='--ask-become-pass'
```

Затем повторить `bootstrap` и `deploy`, проверить сохранение рабочих данных,
перезагрузить VM и повторить `verify-all`. С другого компьютера выполнить curl,
который печатает `verify-gateway`. Сохранить версии ОС, архитектуру, дату,
результаты и обезличенные отчеты из `/var/log/devops-foundation/`.
Полный список: [acceptance.md](acceptance.md).

После успешного испытания обновить статусы в README и паспорте, повторно проверить
публичное клонирование `main` и пересобрать конкурсный ZIP до установленного срока.
Не добавлять в Git kubeconfig, реальные inventory/config, SSH-ключи, токены,
персональные данные или необработанные диагностические отчеты.

## Состояние подготовленного пакета

Подготовлены исходники и документация всех обязательных технических компонентов.
Подтверждены 90 локальных тестов, синтаксис 11 Ansible playbooks и контрольные суммы
vendor-файлов. Promtool проверил 7 правил и 3 тестовых сценария.
Ubuntu VM пока не предоставлена: установка, повторяемость, HTTP, реальные метрики
и доставка логов на целевой ОС не подтверждены. Полный список ограничений проверки
находится в [local-validation.json](local-validation.json).

Паспорт намеренно содержит этот статус. Не следует заменять его утверждением
«протестировано на Ubuntu 24.04» без реального испытания.

## Пересборка паспорта и архива

Это отдельные инструменты управляющей машины; на Kubernetes VM они не нужны.
Для паспорта требуется шрифт DejaVu Sans или Arial. При необходимости передайте
`--font-dir` в скрипт сборки паспорта.

```bash
python3 -m venv .venv-docs
.venv-docs/bin/pip install -r requirements-docs.txt
.venv-docs/bin/python scripts/build_passport.py
.venv-docs/bin/python scripts/package_submission.py --surname Фамилия
```

Изменения текста паспорта вносятся в `scripts/build_passport.py`. После пересборки
нужно визуально проверить все четыре страницы. Скрипт упаковки проверяет число
страниц, размеры и точный состав ZIP; он не проверяет работу стенда и доступность Git.
Результат появляется в `artifacts/submission/`, который исключен из Git.
